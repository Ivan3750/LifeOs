# LifeOs

Особиста «жива ОС» на Next.js: фокус-таймер, задачі, звички, здоровʼя, фінанси в данських кронах (DKK), цілі з колесом балансу, розклад з підключеними календарями і режим компанії (угоди, проєкти, рахунки, команда).

## Запуск

1. Скопіюй `.env.example` у `.env` і заповни:
   - `APP_PASSWORD` — пароль для входу в дашборд (без нього застосунок не відкриється);
   - `DB_*` або `DATABASE_URL` — MySQL, наприклад Aiven.
2. Перевір базу і запусти:

```bash
npm install
npm run db:check
npm run dev
```

Відкрий http://localhost:3000 і увійди з `APP_PASSWORD`.

## База даних і синхронізація

- Увесь стан дашборду зберігається одним JSON-документом у таблиці `pulse_state` (створюється автоматично) з номером версії.
- Зміни записуються в базу через ~1 с після редагування. Інші пристрої підтягують нову версію кожні 15 с і при поверненні у вкладку.
- Якщо два пристрої змінили дані майже одночасно, зміни обʼєднуються за записами (`id`): додане на одному пристрої й відредаговане на іншому зберігається. Якщо обидва змінили те саме значення, перемагає пристрій, що зберігає другим. Видалення не повертається, якщо інший пристрій не змінював цей запис.
- Місце в застосунку, тема, режим і сповіщення належать пристрою й не синхронізуються, тож перехід між розділами не створює конфліктів.
- Кожне видалення можна скасувати кнопкою «Скасувати» в повідомленні внизу екрана.
- Без мережі все працює з `localStorage` і дозаписується, коли зʼєднання повернеться. У production-збірці є service worker і `manifest`: застосунок можна «встановити» на телефон, а останню відвідану сторінку він відкриє й без мережі. Після виходу з акаунта цей офлайн-кеш очищується.
- Усе зберігається одним документом до 8 МБ, а `localStorage` у браузері дозволяє близько 5 МБ. Застосунок попередить, коли даних стає забагато (тоді зроби експорт і видали старі записи).
- Налаштування → «Відновити з копії» завантажує файл, збережений через «Усі дані (JSON)».
- Якщо база не налаштована, дашборд працює лише локально (видно в Налаштуваннях → Синхронізація).
- Перший вхід із базою, де ще немає даних, завантажує туди дані з цього браузера.

**Aiven:** `DB_SSL=true` обовʼязково. Сертифікат бази перевіряється завжди, а Aiven використовує власний CA, тому завантаж «CA certificate» зі сторінки сервісу і вкажи шлях (або сам текст PEM) у `DB_CA_CERT` (файли `*.pem` не потрапляють у git). Лише для тестів можна вимкнути перевірку через `DB_SSL_INSECURE=true`: шифрування лишиться, але захисту від підміни сервера не буде. Також переконайся, що в Aiven дозволено підключення з твоєї IP-адреси (або з хостингу, де працює застосунок).

## Вхід

- Пароль перевіряється на сервері, сесія живе 30 днів у cookie `HttpOnly`.
- 5 неправильних спроб блокують вхід з цієї адреси на хвилину, а 20 спроб з усіх адрес за 10 хвилин блокують вхід для всіх на хвилину. Лічильники живуть у памʼяті процесу: на serverless-хостингу (наприклад, Vercel) кожен інстанс рахує окремо, тож там сильний пароль важливіший за ліміт спроб.
- Сесія — підписаний cookie без списку на сервері, тому окремий пристрій відкликати не можна: «Вийти» лише стирає cookie, а змінити `APP_PASSWORD` виводить усі пристрої.
- Зміна `APP_PASSWORD` (або `SESSION_SECRET`) виводить усі пристрої.
- Кнопка «Вийти» — в Налаштуваннях.

## Календар (iCal)

Календар підключається через секретне iCal-посилання (`.ics`). Підходять Google Calendar, Outlook, iCloud і будь-який інший календар з iCal-експортом. Події доступні лише для читання. Сервер завантажує лише публічні `https`-адреси: адреси локальної мережі, `localhost` та перенаправлення на них відхиляються.

Є два способи:

1. **У застосунку:** Налаштування → «Мої календарі» → встав посилання. Воно входить у твої дані (зберігається в браузері і, якщо підключена база, в MySQL) і передається лише на твій власний сервер `/api/calendar`.
2. **Через змінну середовища:** скопіюй `.env.example` у `.env.local` і заповни `ICAL_URLS` (через кому). Так посилання залишаються тільки на сервері.

Де взяти посилання:

- **Google:** Налаштування → обери календар → «Інтеграція календаря» → «Секретна адреса у форматі iCal».
- **Outlook:** Налаштування → Календар → «Спільні календарі» → «Опублікувати календар» → ICS.
- **iCloud:** Календар → «Поділитися» → «Публічний календар» → посилання `webcal://`.

Сервер завантажує календарі, розгортає повторювані події з урахуванням часових поясів, винятків і перенесень, і повертає події на 2 тижні назад і 60 днів уперед. Синхронізація відбувається при запуску, кожні 10 хвилин і за кнопкою «Оновити».

## Структура

- `app/api/state/route.ts` — читання і збереження стану в MySQL з перевіркою версії
- `app/api/login/route.ts`, `lib/server/auth.ts` — вхід за паролем і підпис сесій
- `lib/server/db.ts` — пул зʼєднань MySQL (`mysql2`), SSL, створення таблиці
- `scripts/db-check.mjs` — `npm run db:check`, перевірка зʼєднання без виводу паролів
- `app/api/calendar/route.ts` — завантаження і розбір iCal (`ical.js`)
- `lib/store.tsx` — стан, синхронізація з базою, таймер, календар; `lib/actions.ts` — усі зміни даних; `lib/merge.ts` — обʼєднання змін двох пристроїв
- `lib/server/safe-fetch.ts`, `lib/server/ical.ts` — безпечне завантаження і розбір календарів
- `public/sw.js`, `app/manifest.ts` — офлайн-кеш і встановлення як застосунку
- `lib/seed.ts` — демо-дані (прибираються в Налаштуваннях)
- `lib/util.ts` — дати, форматування крон, константи
- `components/views/*` — екрани
- `components/Shell.tsx`, `Sheets.tsx`, `Palette.tsx` — оболонка, швидке додавання, командна палітра

## Команди

- `npm run dev` — розробка
- `npm run build && npm start` — продакшн
- `npm run lint`, `npm run typecheck`, `npm test` — перевірки; `npm run check` запускає всі три

## CI

Тести лежать у `tests/` (vitest). GitHub Actions (`.github/workflows/ci.yml`) запускає lint, typecheck, тести й збірку на кожен pull request.
