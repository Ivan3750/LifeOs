# Pulse OS

Особиста «жива ОС» на Next.js: фокус-таймер, задачі, звички, здоровʼя, фінанси в данських кронах (DKK), цілі з колесом балансу, розклад з підключеними календарями і режим компанії (угоди, проєкти, рахунки, команда).

## Запуск

1. Скопіюй `.env.example` у `.env` і заповни:
   - `APP_PASSWORD` — пароль для входу в дашборд (без нього застосунок не відкриється);
   - `DB_*` або `DATABASE_URL` — MySQL, наприклад Aiven.
2. Перевір базу і запусти:

```bash
npm install
npm run db:check
npm run dev
```

Відкрий http://localhost:3000 і увійди з `APP_PASSWORD`.

## База даних і синхронізація

- Увесь стан дашборду зберігається одним JSON-документом у таблиці `pulse_state` (створюється автоматично) з номером версії.
- Зміни записуються в базу через ~1 с після редагування. Інші пристрої підтягують нову версію кожні 15 с і при поверненні у вкладку.
- Якщо два пристрої змінили дані майже одночасно, перемагає той, хто зберіг першим, а другий завантажує його версію (останню локальну правку на ньому треба повторити).
- Без мережі все працює з `localStorage` і дозаписується, коли зʼєднання повернеться.
- Якщо база не налаштована, дашборд працює лише локально (видно в Налаштуваннях → Синхронізація).
- Перший вхід із базою, де ще немає даних, завантажує туди дані з цього браузера.

**Aiven:** `DB_SSL=true` обовʼязково. Щоб сертифікат бази перевірявся повністю, завантаж «CA certificate» зі сторінки сервісу і вкажи шлях у `DB_CA_CERT` (файли `*.pem` не потрапляють у git). Без нього зʼєднання все одно шифроване, але сертифікат не перевіряється. Також переконайся, що в Aiven дозволено підключення з твоєї IP-адреси (або з хостингу, де працює застосунок).

## Вхід

- Пароль перевіряється на сервері, сесія живе 30 днів у cookie `HttpOnly`.
- 5 неправильних спроб блокують вхід з цієї адреси на хвилину.
- Зміна `APP_PASSWORD` (або `SESSION_SECRET`) виводить усі пристрої.
- Кнопка «Вийти» — в Налаштуваннях.

## Календар (iCal)

Календар підключається через секретне iCal-посилання (`.ics`). Підходять Google Calendar, Outlook, iCloud і будь-який інший календар з iCal-експортом. Події доступні лише для читання.

Є два способи:

1. **У застосунку:** Налаштування → «Мої календарі» → встав посилання. Воно зберігається в браузері і передається лише на твій власний сервер `/api/calendar`.
2. **Через змінну середовища:** скопіюй `.env.example` у `.env.local` і заповни `ICAL_URLS` (через кому). Так посилання залишаються тільки на сервері.

Де взяти посилання:

- **Google:** Налаштування → обери календар → «Інтеграція календаря» → «Секретна адреса у форматі iCal».
- **Outlook:** Налаштування → Календар → «Спільні календарі» → «Опублікувати календар» → ICS.
- **iCloud:** Календар → «Поділитися» → «Публічний календар» → посилання `webcal://`.

Сервер завантажує календарі, розгортає повторювані події з урахуванням часових поясів, винятків і перенесень, і повертає події на 2 тижні назад і 60 днів уперед. Синхронізація відбувається при запуску, кожні 10 хвилин і за кнопкою «Оновити».

## Структура

- `app/api/state/route.ts` — читання і збереження стану в MySQL з перевіркою версії
- `app/api/login/route.ts`, `lib/server/auth.ts` — вхід за паролем і підпис сесій
- `lib/server/db.ts` — пул зʼєднань MySQL (`mysql2`), SSL, створення таблиці
- `scripts/db-check.mjs` — `npm run db:check`, перевірка зʼєднання без виводу паролів
- `app/api/calendar/route.ts` — завантаження і розбір iCal (`ical.js`)
- `lib/store.tsx` — стан застосунку, дії, таймер, синхронізація календаря
- `lib/seed.ts` — демо-дані (прибираються в Налаштуваннях)
- `lib/util.ts` — дати, форматування крон, константи
- `components/views/*` — екрани
- `components/Shell.tsx`, `Sheets.tsx`, `Palette.tsx` — оболонка, швидке додавання, командна палітра

## Команди

- `npm run dev` — розробка
- `npm run build && npm start` — продакшн
- `npm run lint`, `npm run typecheck` — перевірки
